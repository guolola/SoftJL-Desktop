# 建模能力

- 维护状态：持续维护
- 目标读者：桌面版使用者与维护者
- 事实来源：`src/shared/contracts/workspace/standard-project.ts`、`src/main/modeling/runs/pipelines/standard/` 与图表渲染器

## 概述

项目统一通过持续对话梳理需求，按需生成和修改模型、测试用例及说明书。模型使用当前结构化契约，不接受旧通用节点与连线格式。

## 当前设计或配置

支持功能结构、用例、业务流程、总体架构、概念 E-R、设计类、时序和数据库表关系八类模型。同类业务流程和时序可以保存多张业务图。七类模型共用结构语义与 PlantUML 渲染器；E-R 保存实体、属性与关系，并使用独立确定性源码构建。

生成工具每次只进行一次内容生成、结构校验和渲染。失败时返回目标、真实错误及可用的候选结构，由 Pi Agent 决定修正、重新生成、询问用户或停止；工具内部不自动返修内容，传输层的网络与临时服务错误重试继续保留。无效候选结构仅作为工具结果返回，不写入已保存模型。

本轮实际处理的图表单独记录，侧栏在本轮运行期间将这些图表的失败尝试显示为处理中；本轮结束后按实际结果显示成功或失败。历史失败图不因无关任务启动而变成处理中，成功产物及时展示并保留。

图表页支持预览、元素与关系编辑，以及 SVG、PNG、PDF 和 PlantUML 下载。测试页展示会话生成的实际用例、分类、优先级与业务关联，不宣称已经执行程序测试。说明书支持需求规格说明书和软件设计说明书，可预览、下载及管理版本。

模型、测试和说明书的选择由用户请求与会话范围确认决定。不存在分阶段工作区、可行性流程、需求基线、来源追踪矩阵或变更影响审核页面。

## 操作与维护

创建项目后在聊天中描述业务与需要生成的产物。代码生成沿用聊天中的本地代码工具，代码目录在项目创建或项目设置中选择。只读成员可以查看，修改与执行任务仍由项目权限和原生工具权限控制。

新增图种须同步修改模型契约、结构校验、渲染器、编辑器和会话工具守卫，不能只修改提示词。

## 验证

运行 `npm run typecheck`、`npm run test:modeling`、`npm run test:renderer` 与 `npm run audit:docs`。真实模型与供应商行为需单独验证。
